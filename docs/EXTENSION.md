# 浏览器扩展：从私人实现到通用参考

我们的 Chrome 扩展最初为特定的双入口聊天环境开发，经历过多轮网页结构适配、游标去重和故障修复。整理开源版本时，我们保留了**当前网页采集 → 增量裁剪 → collector → ACK** 的核心思路，把私人服务和历史迁移细节留在自己的部署里。

仓库的 [`examples/extension`](../examples/extension) 提供可以动手试的 Manifest V3 示例：`manifest`、`content`、`background`、`extractor` 和 `popup` 都在。先用 **Capture preview** 看它识别到了哪些可见消息，配置自己的 collector 后再选择开启上传。

## 我们的实现与仓库示例

| 功能 | 我们使用的实现 | 仓库示例 |
| --- | --- | --- |
| 会话身份 | URL route + API／DOM 身份校验 | 验证当前 `/c/<id>` |
| 消息来源 | 网页可见文本，辅以登录态网页响应 | DOM 中的可见文本 |
| 去重 | 会话 ID、稳定消息 ID、辅助指纹与消费游标 | 简化的消息 ID 增量 |
| 交接 | 任务状态、超时、ACK、失败终态 | 本地 collector 演示 |
| 记忆 | 独立长期记忆、档案和短期事件库 | 指令模板 + 短期存储 |
| iOS 换窗 | 网页需打开目标会话 | 同样需要当前正确的网页 |

这份示例适合阅读、实验和继续改造。不同版本的网页可能需要调整 DOM 选择器；也可以在此基础上适配其他 AI 聊天网站。

## 接到自己的环境

1. 在独立项目目录里整理配置，把 relay 地址、密钥与消息存储方式放到本地配置中。
2. 先运行预览，检查页面身份、角色识别和消息顺序。
3. 配置自己的 HTTPS／私网入口与认证，并限制扩展可连接的地址。
4. 加入窗口切换、同文不同 ID、流式回复、重复 ACK 和失败后恢复等回归测试。
5. 引入其他开源代码时，依照对应许可证保留作者、版权和许可信息。
